# Code Spec: Phase 1 Static Unit Registry Release

**This file is supporting implementation detail for the complete prose [spec](spec.md).**
It introduces no independent requirements. Its `implements` annotations provide cross-document traceability rather than DAG citations within a second hierarchical spec.

**Phase 1 consolidates the implemented Python, JavaScript, shared-registry, and polish work without changing supported entry points.** _(implements "Phase 1 preserves the shared registry and pricing invariants", "Phase 1 must be independently shippable and releasable", "Pricing accuracy is the Phase 1 product outcome", "Phase 1 preserves supported consumer behavior unless accurate registry pricing makes that impossible", "Public pricing and snapshot APIs keep their callable shape", "Manual Python pricing extensions remain supported")_
Context: keep the branch's registry-backed pricing, usage, validation, generated authoring schema, direct Python `ModelPrice` storage, raw-provider normalization, and registry-driven CLI behavior. Change only the remote-payload and registry-lifecycle implementation needed for the static v2 contract. The public functions and methods named in the prose spec retain their argument and return shapes; internal helpers may gain explicit registry or resolved-price parameters.

**Source units remain flat usage-keyed YAML and define the complete pricing graph.** _(implements "Units are repo-defined data used by handwritten runtime code", "Dimensions define containment, overlap, and cost aggregation", "Every priced usage value lands in exactly one bucket", "`requests_kcount` remains an explicit one-request pricing exception", "`web_searches_kcount` prices reported web searches")_
Maintain `prices/units.yml` as the source registry. Each unit's runtime-semantic fields are `per`, optional `price_key`, and `dimensions` with `family`. Source units may additionally carry build-only information for publication validation. The current source uses `dimension_requirements` to state that `cache_ttl` requires `token_type: cache_write`, but neither that field name nor that validation representation is a runtime contract; build code may replace it while preserving the structural rule. The complete built-in token lattice uses mutually exclusive `token_type` values for cache read/write, input tool-use, output reasoning, and output citation categories. Cache-write duration adds `cache_ttl`. The lattice includes the intermediate and join units required for input/output and supported modality overlap, without cross-category joins. `requests` remains the pricing-only unit with `requests_kcount` and `per: 1_000`; `web_searches` is the reportable singleton `tool_calls` family unit with `web_searches_kcount` and `per: 1_000`. `packages/python/genai_prices/decompose.py` and `packages/js/src/decompose.ts` continue computing exclusive buckets from `UnitDef.dimensions`; they receive only the priced non-request units resolved for the current calculation.

**Named build/export validation functions remain reusable and authoritative.** _(implements "Price data is complete while usage data may be incomplete", "Repo-authored prices avoid redundant equal-rate descendants", "Build/export validation is the authoritative publication boundary", "Model prices are still validated on use", "Extractor destinations are externally reported bundled-registry usage keys", "Provider YAML authoring derives allowed keys from the registry")_
`prices/src/prices/export_validation.py` owns `validate_units(raw_units: Mapping[str, Mapping[str, object]]) -> UnitRegistry` and `validate_export_payload(providers: list[Provider], raw_units: Mapping[str, Mapping[str, object]]) -> UnitRegistry`. `validate_units(...)` enforces unique usage keys, price keys, and dimension sets; the shared public-identifier, keyword, leading-underscore, and prototype-hazard restrictions; a strictly positive integer `per` value and one shared value per family; valid conditional-dimension structure; exact interval closure over structurally valid dimension sets; and join-closedness. Build-only parsing and temporary validation records may be as rich as needed, but the returned `UnitRegistry` and generated unit projection discard source-only fields. `prices/src/prices/package_data.py` owns `validate_provider_model_prices(providers: list[Provider], registry: UnitRegistry) -> None` and `validate_provider_extractor_destinations(providers: list[Provider], registry: UnitRegistry) -> None`. The build calls these functions as part of provider-data publication and raises on every unknown price key or extractor destination; registry-derived JSON Schema price properties receive a title from the price key and a description from the unit normalization and usage key; repo-data regression tests enforce the equal-rate-child convention and exact built-in naming patterns. Runtime registry construction indexes trusted generated units without repeating publication validation. The named strict validation helpers remain available for build code and isolated validation, while standard runtime entry points project onto recognized units with warnings before applying recognized-unit semantic validation.

**Python and JavaScript each construct one generated registry.** _(implements "The Phase 1 registry is static for the lifetime of the installed package", "`UnitRegistry` is immutable indexed metadata after construction")_
`packages/python/genai_prices/units.py` retains `UnitDef`, `UnitRegistry(raw_units: Mapping[str, Mapping[str, object]])`, and `_get_registry() -> UnitRegistry`; `UnitDef` contains only usage key, resolved price key, normalization, and dimensions. `_get_registry()` lazily constructs `_bundled_registry` from `genai_prices.data_units.unit_data` and always returns that object. Remove `_active_registry` and `_set_registry`. `packages/js/src/units.ts` constructs one `generatedRegistry` with `new UnitRegistry(rawUnits: RawUnitsDict)` from `dataUnits.ts`; TypeScript `RawUnitData` contains normalization, dimensions, and an optional distinct price key, while `UnitDef` materializes both identities. Neither runtime type contains build-only validation metadata. Its getters always read that object, and `setActiveRegistry` plus mutable `activeRegistry` state are removed. Validation helpers continue accepting an explicit `UnitRegistry` for build code and isolated tests.

`DataSnapshot` remains provider-only. `set_custom_snapshot(snapshot: DataSnapshot | None) -> None` replaces or clears only provider data; snapshots do not carry or replace the bundled registry, and activation does not bulk-validate model prices. Standard base pricing continues validating only the selected model price on use.

`UnitRegistry.__init__` and the TypeScript constructor precompute usage-key, price-key, dimension, ancestor, join, all-key, reported-key, and reported-key-order indexes. Python exposes `units` as a read-only mapping and stores protected `_reported_usage_keys: frozenset[str]` and `_reported_usage_keys_in_order: tuple[str, ...]` indexes once instead of recreating them for every `Usage` operation. JavaScript keeps its map/set indexes in ECMAScript-private fields, exposes only lookup, read-only iteration, membership, and defensive-copy methods needed by runtime consumers, and freezes each constructed `UnitDef` and its dimensions so callers cannot mutate registry metadata.

**Generated provider and unit modules remain separate.** _(implements "Generated package providers and units have separate inputs")_
`prices/src/prices/package_data.py` generates:

- `packages/python/genai_prices/data.py` from the v2 provider array;
- `packages/python/genai_prices/data_units.py` from validated `prices/units.yml` data;
- `packages/js/src/data.ts` from the v2 provider array;
- `packages/js/src/dataUnits.ts` from the same validated unit data.

Generated provider files do not embed registries, and generated unit files do not import provider data. Unit generation retains the source mapping key as usage identity and projects every record to `per`, `dimensions`, and `price_key` only when distinct from that usage key. It does not serialize `dimension_requirements` or any future source-only validation field. Generated files contain runtime data only.

**V1 remote artifacts are no longer build outputs.** _(implements "The existing v1 JSON artifacts remain outside Phase 1 build output")_
When `prices/src/prices/build.py` starts emitting `prices/new_data/v2/data.json`, it and `prices/src/prices/package_data.py` stop opening `prices/data.json`, `prices/data_slim.json`, `prices/data.schema.json`, or `prices/data_slim.schema.json` for writing. Earlier implementation slices continue regenerating v1 so clients receive current price data until v2 exists.

**Explicit v1 maintenance remains compatible with released clients.** _(implements "Deliberate v1 maintenance preserves released-client compatibility rather than byte identity")_
After the cutover, the existing URLs and provider-array contracts remain compatible with old packages. Load the common baseline schema with `git show ba8093719f296a3672ff4b2fc848a122e92a049c:prices/data.schema.json` and validate both checked-in v1 payloads against it. No payload byte-level pin is required, and current schema artifacts are not compatibility baselines.

**The build emits full and slim v2 provider arrays with a frozen unit vocabulary.** _(implements "Phase 1 publishes full and slim provider-array v2 data", "The v2 unit vocabulary is frozen")_
`prices/src/prices/build.py` writes current publishable providers to `prices/new_data/v2/data.json` with the same top-level array shape as v1 and writes `prices/new_data/v2/data.schema.json` from the provider model plus the Phase 1 registry's allowed price and extractor keys. It also writes `prices/new_data/v2/data_slim.json` and `prices/new_data/v2/data_slim.schema.json` after excluding free models, provider `pricing_urls`, `description`, and `price_comments`, and model `name`, `description`, and `price_comments`. `prices/src/prices/package_data.py::package_data()` reads providers from the full v2 artifact and units independently from `prices/units.yml`. No v2 artifact contains `units`, validation state, or cached plans. Before Phase 2 exists, price releases may update both v2 variants only when every price key and extractor destination is accepted by their checked-in schemas; adding a unit requires v3 instead.

**Python auto-update parses only v2 provider arrays.** _(implements "Phase 1 auto-updaters use only the full v2 artifact")_
In `packages/python/genai_prices/update_prices.py`, set `DEFAULT_UPDATE_URL` to the raw `prices/new_data/v2/data.json` URL. `UpdatePrices.fetch()` requires a JSON array, passes it to `packages/python/genai_prices/types.py::_providers_from_raw`, warns about extractor destinations unsupported by `_get_registry()`, and returns a provider-only `DataSnapshot`. It never imports a registry setter or constructs a candidate registry. `UpdatePrices.stop()` clears the custom provider snapshot without touching unit state.

**JavaScript auto-update parses only v2 provider arrays.** _(implements "Phase 1 auto-updaters use only the full v2 artifact")_
In `packages/js/src/api.ts`, set `REMOTE_DATA_JSON_URL` to the raw `prices/new_data/v2/data.json` URL and narrow `ProviderDataValue` in `packages/js/src/types.ts` to `null | Provider[]`; remove `WrappedProviderData`. `setProviderData` accepts that value or a promise resolving to it. `activateProviderData(providers: Provider[]): Provider[]` warns about unsupported extractor destinations before replacing and returning `providerData`; `null`, rejection, invalid arrays, and stale rejected promises retain the previous providers. Remove wrapped-payload parsing and registry activation.

**Python `Usage` and `ModelPrice` retain the completed direct-storage design.** _(implements "Manual Python pricing extensions remain supported", "Python `Usage` stores reported registry values directly", "Python `ModelPrice` uses direct public attribute storage", "Runtime provider parsing is an internal normalization step")_
In `packages/python/genai_prices/types.py`, `Usage` stores reported values in `__dict__`, filters them through bundled reported-key indexes for equality, representation, and addition, and performs explicit-only missing reads through bundled relationships. Direct construction warns once for the sorted unknown or pricing-only names and stores them as ordinary attributes outside those standard operations. `Usage.from_raw(...)` reads attributes rather than mappings, silently ignores unknown source attributes for base pricing, and returns the registry-shaped copy while `ModelInfo.calc_price(...)` still passes the original usage to an overridden `ModelPrice.calc_price(...)`. Registered assignment stores or removes a reported value; unrelated names use ordinary object assignment. Base `ModelPrice` calculation likewise warns once for sorted unknown stored price names, omits them from its resolved-price collection, and continues to reject incomplete ancestor or join coverage among recognized prices; subclass-only custom state remains excluded without warnings.

`ModelPrice` remains a plain class with arbitrary price keyword arguments stored directly as public attributes. It has no metaclass, dataclass price fields, Pydantic core-schema customization, or `_extra_prices` mapping. `__getattr__` returns `None` only for absent bundled price keys; ordinary assignment and deletion remain unhooked. Effective-price collection excludes subclass-only custom state, and custom dataclass subclass constructors need not accept undeclared dynamic price keywords.

`_providers_from_raw(raw_providers: object) -> list[Provider]` is private runtime plumbing. It recursively normalizes flat and conditional price mappings, validates each price mapping as `dict[str, Decimal | TieredPrices | None]`, constructs `ModelPrice`, and then validates the surrounding provider dataclasses through a Pydantic adapter configured with `arbitrary_types_allowed=True`. Package-data generation and `UpdatePrices.fetch()` use this helper; provider-YAML schema generation continues using the build-time models.

**Python extractor construction retains its public validation boundary.** _(implements "Extractor destinations are externally reported bundled-registry usage keys", "Python extractor construction keeps its public compatibility boundary")_
In `packages/python/genai_prices/types.py`, `UsageExtractorMapping.dest: str` remains the destination field. `UsageExtractor.__post_init__(self) -> None` checks mappings against its supplied or bundled registry and emits one warning listing sorted unsupported arbitrary names, price keys, and pricing-only destinations. `UsageExtractor.extract(response_data: object) -> tuple[str | None, Usage]` skips unsupported mappings before reading their paths, accumulates recognized counts, and returns registry-shaped reported usage without performing eager cross-field consistency validation.

**JavaScript retains open records and direct registry-aware usage reads.** _(implements "JavaScript retains plain usage and model-price objects", "Price data is complete while usage data may be incomplete", "`requests_kcount` remains an explicit one-request pricing exception")_
`packages/js/src/types.ts` retains `Usage = Record<string, number | undefined>`, `ModelPrice = Record<string, number | TieredPrices | undefined>`, and `UsageExtractorMapping.dest: string`. Provider activation and direct extraction warn about destinations unsupported by `generatedRegistry`; extraction skips those mappings before reading their paths, accumulates recognized counts by usage key, and returns a normalized plain `Usage`. `packages/js/src/usage.ts::normalizeUsage(...)` is used for extractor and normalized-return paths, while `packages/js/src/engine.ts::calcPrice(...)` reads the caller object directly, emits one warning listing sorted unsupported usage keys, and otherwise ignores them. Price collection emits one warning listing sorted unknown price keys and excludes them before validating recognized ancestor and join coverage. Missing-value safety, tier thresholds, one synthesized request, decomposition, and dimension-based aggregation match Python behavior.

**Both runtimes validate and price through one per-call structural collection.** _(implements "Phase 1 must avoid an unreasonable pricing hot-path regression", "Phase 1 removes repeated structural work from the pricing hot path", "JavaScript model validation materializes key and unit collections once")_
In `packages/python/genai_prices/types.py`, add `_collect_resolved_model_prices(model_price: ModelPrice, registry: UnitRegistry) -> tuple[tuple[UnitDef, Decimal | TieredPrices], ...]`. In `packages/js/src/engine.ts`, define `ResolvedPrice = Readonly<{ unit: UnitDef; price: number | TieredPrices }>` and `collectResolvedModelPrices(modelPrice: ModelPrice, registry: UnitRegistry): ResolvedPrice[]`; it forms one collection from the non-undefined `Object.entries(modelPrice)`. Each collector resolves registered units once, warns once about sorted unknown base price keys and omits them, and excludes subclass-only custom Python state without warning. Use this collection for:

- price-key, ancestor, and join validation;
- selecting non-`requests` decomposition units;
- determining whether any current price value is tiered;
- reading current price values;
- normalization and result aggregation.

`packages/python/genai_prices/validation.py` adds `validate_priced_units(priced_units: Collection[UnitDef], registry: UnitRegistry) -> None`, and `packages/js/src/validation.ts` adds `validatePricedUnits(pricedUnits: readonly UnitDef[], registry: UnitRegistry): void`. Existing key-based validation functions resolve keys once and delegate; the standard pricing functions call the resolved-unit form directly. They do not scan all registry units separately for key collection, unit collection, and tier detection.

**Decomposition stays direct and uncached.** _(implements "Every priced usage value lands in exactly one bucket", "Phase 1 deliberately excludes runtime-updated units and performance caches")_
Compute exclusive values from the resolved priced-unit collection and current explicit usage on every calculation. Process units from most specific to least specific; each bucket is its reported usage minus the already-exclusive buckets of all strict priced descendants. This works for both orthogonal and requirement-conditional dimensions without relying on dimension-count parity. Do not add model-object caches, registry validation IDs, weak references, fingerprint state, prepared pricing plans, or decomposition coefficient caches.

**Authoring schemas and CLI remain registry-driven.** _(implements "Provider YAML authoring derives allowed keys from the registry", "CLI price presentation is registry-driven", "Phase 1 preserves the existing CLI surface")_
Provider YAML schema generation derives price-key and extractor-destination suggestions from the validated source registry. Repo-data tests enforce `_tokens`, `_mtok`, and the checked-in naming convention for direction, modality, `token_type`, and cache TTL combinations only for built-in token units; schema and runtime validation do not encode those token concepts.

In `packages/python/genai_prices/_cli.py`, `_collect_model_price_fields(results: Sequence[PriceCalculation]) -> list[str]` discovers stored/effective price keys, `_price_field_label(field_name: str) -> str` derives a display label from bundled unit dimensions and normalization, `_format_model_price_value(model_price: ModelPrice, field_name: str, *, use_color: bool) -> Text` formats one value generically, and `_format_model_prices(model_price: ModelPrice, *, split_lines: bool, use_color: bool) -> Text` combines the registered stored values. Existing CLI flags and option semantics remain compatible. Derived label wording follows current dimensions and does not add compatibility aliases or hardcoded branches when those dimensions change.

**Tests replace wrapped-payload lifecycle coverage with static-v2 coverage.** _(implements "Tests prove the complete releasable contract", "Deliberate v1 maintenance preserves released-client compatibility rather than byte identity")_
Keep registry identity, normalization, public-name, interval/join closure, usage, decomposition, dynamic and misspelled price keys, modality prices, mixed aggregate output whose detail array omits the default text remainder, raw-provider normalization, schema, naming, CLI, custom-pricing, generated-output purity, and cross-runtime parity coverage. Explicitly test that source-only unit validation metadata affects publication checks but is absent from generated unit data, Python `UnitDef`, and TypeScript `RawUnitData`/`UnitDef`. Include the `Usage.from_raw(...)` attribute-object boundary and its silent handling of unrelated attributes, ordinary unrelated usage attributes, direct `ModelPrice` storage without a side mapping, custom subclass state excluded without warnings, flat and tiered dynamic prices, deterministic runtime warnings and omission for unknown direct usage names, base price keys, and extractor destinations, strict build-time rejection of unknown provider price keys and extractor destinations, extractor inconsistency remaining lazy, existing CLI flags and output, no eager provider-activation model-price validation, and alignment with the shared examples. Replace tests for wrapped roots, candidate registry installation, registry rollback, and reset-on-stop with tests that:

- build and package-data paths do not write v1 artifacts, and both checked-in v1 payloads validate against the common baseline schema;
- v2 and its schema are provider-array artifacts with new registered keys;
- package unit data comes from the source registry rather than v2;
- successful and failed provider updates preserve the bundled registry identity;
- both auto-updaters point at v2;
- the hot path reuses one structural collection without behavior drift.
